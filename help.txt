RastaConverter by Jakub 'Ilmenit' Debski

Usage:
RastaConverter.exe InputFile [options]

To save the output during the optimization process, press the 's' key.

Copy created output files to the directory Generator or GeneratorDual (for dual mode) and run 'build.bat' to create executable file.

Started with no arguments (or with /livegui), the application opens the
interactive setup screen and live dashboard instead; the display described below
is what a command-line conversion shows.

The application displays three images:
- the left one is the original picture resized to Atari width.
- the right one is the original picture mapped to chosen Atari palette. This is our goal to reach.
- the central one is a preview of the output picture.

If the colors on the right image are wrong (e.g. too gray) then try a different palette file
or remap original picture to chosen palette file using other another tool e.g. Timanthes.
Below on the screen are some statistics from the optimization process.
With the current algorithm the longer you wait, the better results you get. 
For some pictures, more than 1 million evaluations are needed to get really good results.
Some users wait set high /s and wait 1+ billion evaluations to get the best quality output.

Dual-frame mode (two frames A/B alternating):
- Enable with /dual (or --dual=on). 
- Bootstrap A for /first_dual_steps evaluations, then B (copy A or generate fresh) for /first_dual_steps (if /after_dual_steps=generate)
- Alternate optimizing A/B every /altering_dual_steps evaluations
- In dual mode, the central preview shows:
  - A, B, or Mixed (blended) — toggle with keys: [A], [B], [M]
  - Status lines under stats: Optimizing: A|B; Showing: A|B|M; Press [A] [B] [M]ix
- Note: Mutation statistics are shown only in single-frame mode (hidden in dual mode)
  - Optimizer and history: /opt (lahc|dlas|legacy) and /s (history length) work exactly the same as in single-frame mode; dual mode uses the same acceptance logic and history

Command line options (accept '/', '-' or '--' prefixes; aliases included under each option):

General options:

/v, --version
  Show version information and exit.

/o=Output File
  Output file names. The default names are 'output.*' and 'out_dual.*' in dual mode.
  Using a different name you have to change the file names used in the Generator.
  Aliases: -o, --output

/threads=number of threads
  Set the number of processing threads. Values above the machine's reported
  hardware-thread count are clamped when that count is available.
  Aliases: /t, --threads

/max_evals=Maximum number of evaluations
  RastaConverter will save the current solution and exit when this limit is reached.
  Aliases: /me, --max_evals

/save=number of solutions or auto
  Default: auto
  To disable set: 0
  Saves best solution after every 'n' evaluations. When 'auto' is used then 'n' is dynamically calculated according to conversion ratio to save each 30 seconds.
  This is useful for a long-run optimizations, when the run can be stopped by power outage for example. If you run many instances of RastaConverter /o option may be useful.
  Aliases: --save

/continue
  Continue previously stopped process. Currently it uses previously generated files (output*.*) therefore
  be careful not to overwrite them with other instance of RastaConverter. 
  Aliases: --continue
  Notes:
  - Respects the current /output value. If you used /o=custom.png earlier, resume will look for
    custom.png.rp[.ini]/.optstate (single) or out_dual_A/B.rp[.ini] in the same directory (dual).
  - In dual mode, resume automatically loads A and B if present; otherwise falls back to single-frame.
  - Single-frame saved scores reconstruct exactly. Dual scores are re-materialized against the loaded
    opposite frame and may shift slightly before new search work; record that baseline separately.

/subfolder=on|off
  Where a run's files go when the interface derives the name for you. Default: on.
  on writes them into their own folder beside the source image, rc-<image>-NNN, so
    a re-run never disturbs an earlier one and a run stays one self-contained thing.
  off writes them beside the source image directly, taking the plain <image>.png
    name when it is free and numbering it otherwise, so nothing is overwritten.
  A /output path you give yourself always wins over both.
  Aliases: --subfolder

/preprocess
  If this switch exists then RastaConverter generates and saves only destination picture.
  Aliases: --preprocess

/quiet
  Headless/quiet mode (no GUI).
  Aliases: -q, --quiet

/livegui
  Open the interactive setup screen and live conversion dashboard. This is also
  what starting RastaConverter with no arguments does. Options given on the
  command line become the starting settings of the form, and the conversion
  writes into its own rc-<image>-NNN folder beside the input image rather than
  into the current directory.
  Aliases: --livegui

/seed = seed for the random number generator
  Aliases: --seed

Input:

/i=Input File
  File to process. All the formats of the FreeImage library supported, including JPG, PNG, GIF and BMP.
  Warning: it is not possible to load 16 colors pictures (4 bits per pixel). Increase the color depth first
  using other graphics program.
  Aliases: -i, --input

/h=Output Height
  Default: Proportional to picture size rescaled to 320xheight or 240.
  Generated file height. The speed of the optimization process depends on the height.
  Aliases: -h
  
/pal=Palette File
  Default: Palettes\laoo.act
  The output quality depends a lot on similarity between chosen Atari palette and the image palette.
  The default palette covers a large color range and is close to real Atari palette.
  You can also use shortcuts: /pal=laoo and the converter will try to load palette from 'Palettes\laoo.act'
  Note: Using /palette without a value implies the default Palettes\laoo.act
  Aliases: -pal, --palette
  
/dither=Dithering Type
  Possible dithering types are: chess, floyd, 2d, jarvis, simple, knoll
  'chess' is Chessboard Dithering - typical 8bit dithering technique
  'floyd' is Floyd-Steinberg dithering - more "random" than chessboard dithering
  '2d' and 'simple' are between chess and floyd.
  'jarvis' dithering is more artistic
  'knoll' is similar to Adobe patented pattern dithering algorithm. Very slow with /predistance=ciede.
  'line' dithering that tries to keep a low number of color changes on the line
  'line2' similar to 'line'
  Aliases: --dither

/dither_val=Dithering strength
  Default: 1, should be set from 0.0 to 3.0. 
  Some dithering algorithms set to /dither_val=2 may increase color saturation if the output picture is too gray.
  Aliases: --dither_val

/dither_rand=Dithering randomness
  Default: 0, should be set from 0.0 to 1.0
  Current implementation of dithering algorithm produces output which may look too patterned.
  Set /dither_rand to 0.5 or 1.0 to make output more random.
  Aliases: --dither_rand

  Note: the legacy /dither=rfloyd path currently performs per-pixel
  quantization without Floyd error diffusion and does not use /dither_val or
  /dither_rand.

/details=Details picture
  Set an image mask to prioritize selected regions during optimization. The mask is
  box-resized to the 160-pixel target. In compatibility mode, brightness is the
  integer arithmetic mean of encoded sRGB red, green, and blue; alpha is ignored.
  Black keeps normal error weight and white uses up to 1 + /details_val. The mask
  affects direct single-frame pixel error; spatial, edge, region, and dual temporal
  terms are currently unchanged.
  Aliases: --details

/details_val=Details influence strength
  Default: 0.5. Values at or below zero leave direct error unchanged. Very large
  weighted errors saturate instead of wrapping.
  Aliases: --details_val

/details_mode=legacy|normalized|refined
  Default: legacy. Legacy preserves arithmetic encoded-sRGB brightness and its
  historical objective scale. Normalized uses linear-light luminance, exact area
  coverage resizing, a bounded target-space feather, and weights normalized to
  image-wide mean 1. It saves OUTPUT-details-effective.png and reports stable
  decoded-source and effective-map hashes. All modes ignore alpha.
  refined treats the supplied mask as authoritative ROI coverage and derives a
  deterministic bounded importance map inside it from multi-scale source
  luminance/chroma contrast, edges, texture, and boundary distance. It never
  adds source-derived priority outside the supplied ROI.

/details_floor=FLOAT
  Normalized-mode background priority floor, clamped to [0.01,1]. Default: 0.25.

/details_feather=PIXELS
  Normalized-mode target-space box-feather radius, clamped to [0,8]. Default: 1.

  Single-frame `.rp`/`.opt` metadata reports `Unweighted Source OKLab Mean` at
  the converter's native target resolution. The benchmark summary copies this
  field alongside its independent saved-PNG metrics; it never affects search.

/details_refine_mix=FLOAT
  Refined-mode blend between uniform ROI priority (0) and full derived source
  importance (1), clamped to [0,1]. Default: 0.5. This does not change the ROI's
  total salience allocation.

/details_score=on|off
  Default: on. Set off to load a mask for search allocation and reporting without
  multiplying direct pixel error. This permits allocation-only experiments.

/details_allocate
  Bias non-legacy single-frame primary scanline mutation selection using the
  effective mask's mean scanline priority. This is opt-in and independent of
  /details_score.

/details_global_period=N
  With /details_allocate, force one uniform global scanline selection every N
  primary mutations. Clamped to [2,100]; default 5 (20% scheduled exploration).

/filter=Resize filter
  Default: box
  Filter used to resize the picture to the Atari width=160 color pixels (40 bytes). 
	Possible filters are: lanczos, box, bicubic, bilinear, bspline, catmullrom
  Aliases: --filter

/brightness=[-100,100]
  Default: 0
  Brightness color correction.
  Aliases: --brightness

/contrast=[-100,100]
  Default: 0
  Contrast color correction.
  Aliases: --contrast

/gamma=[0.0-8.0]
  Default: 1.0
  Gamma color correction.
  Aliases: --gamma

/saturation=[-100,100]
  Default: 0
  Uniform color saturation adjustment, applied after brightness, contrast and gamma.
  Raising it pushes already-saturated pixels past what the Atari palette can represent,
  so they quantize into the same few entries: saturation goes up while the number of
  distinct colors goes down. Prefer /vibrance when the output looks too gray.
  Aliases: --saturation

/vibrance=[-100,100]
  Default: 0
  Selective saturation adjustment, weighted inversely to each pixel's existing chroma,
  so dull regions gain the most and already-saturated ones are protected. This targets
  the palette's usable midrange, which is normally the better answer to a gray-looking
  result than /dither_val=2.
  Aliases: --vibrance

/init=Initial optimization state
   Default: random
   The optimization search space is large and the final results depends a lot on the initial values.
   You may see that RastaConverter sometimes optimizes not those details of the picture that you want.
   To change the initial value you may use other states: random, empty, less, smart
   
   '/init=less' option sets less colors in the initial state of the picture. This gives better result
   quick, but then picture is harder to optimize than with /init=smart 
  Aliases: --init

/s or --solutions=History length
  History length used by the optimizer (DLAS or LAHC).
  With /s=1 (default) the optimization algorithm is simple hill climbing.
  With larger values, acceptance uses a history window which significantly improves exploration.
  There is no universal best history length; it depends on optimizer, input, run budget, and seed.
  Treat example values as syntax demonstrations until benchmarked quality presets are published.
  Aliases: /s, --solutions
 
 /opt or --optimizer=lahc|dlas|legacy
  Select optimization algorithm. Default: lahc
  - lahc: Late Acceptance Hill Climbing (default)
  - dlas: Diversified Late Acceptance Search
  - legacy: Legacy LAHC behavior
  Aliases: --opt, --optimizer
  
/unstuck_after=<N>
  Default: 0 (disabled)
  Escalate exploration only after N evaluations without improvement (0=never). 
  When triggered, the search uses larger mutation batches and more exploratory edits
  to escape local minima, especially useful in dual mode with anti-flicker. Aliases: /ua, --unstuck_after
  
/unstuck_drift=<FLOAT>
  Default: 0 (disabled)
  When stuck (as per /unstuck_after), slowly relax acceptance by adding FLOAT to the normalized
  distance threshold per evaluation (0=off). This allows accepting
  slightly worse, but different, solutions to escape deep local minima. Aliases: /ud, --unstuck_drift, --unstuck_drift_norm

/distance=Color distance function
  Default: rasta, other options: yuv, euclid, ciede, cie94, oklab
 
  rasta - fast YUV-based distance optimized for Atari palettes. Boosts chroma for dark colors and 
          strongly avoids mapping colored sources to gray palette entries. Best balance of speed and quality.
  yuv - simple YUV distance, fast but tends to map low-saturation colors to grays.
  euclid - Euclidian RGB distance. Fast but not perceptually accurate.
  ciede - CIEDE2000, the most perceptually accurate but VERY slow (not recommended for large images).
  cie94 - legacy CIE94 distance (faster than CIEDE2000, less accurate).
  oklab - modern perceptual distance with good balance of accuracy and speed.
  Aliases: --distance

/objective=target|source
  Which picture a candidate raster program is scored against. Default: target.
  target scores the processed quantized/dithered target picture - the one the GUI
    shows under "Target". This is the historical behavior (the old spelling
    /objective=legacy is still accepted and identical), it keeps scores comparable
    with older runs, and it is the only mode in which the live editor can repaint
    the destination, since the target picture is what a candidate is measured
    against.
  source keeps that processed image as an initialization/mutation guide but scores
    the full-color source picture. It adds no per-evaluation cost - only the
    reference the error tables are built from changes - and measured closer to the
    original on every metric tried: on a photograph and on illustrated artwork at
    240 lines, 150 s per run, it beat target scoring on mean OKLab error, on the
    95th percentile, on SSIM and on gradient fidelity. The gap is widest with
    /dither=none.
  Removed: source-spatial, source-composite, source-edge and source-region each
    added a full-frame structural term to every evaluation. The term cost about
    sixty times the throughput, and in the measurements above none of them beat
    plain source - at equal wall clock or at equal evaluation counts. The four
    names are still accepted and now select source, so an existing recipe keeps
    its intent.
  Dual mode retains its joint objective and ignores this setting.
  Aliases: --objective

/spatial_weight=FLOAT
/edge_weight=FLOAT
/region_weight=FLOAT
  Accepted and ignored. These tuned the removed structural objectives; a recipe
  naming one still runs, and prints a warning saying the value had no effect.
  Aliases: --spatial_weight --edge_weight --region_weight

/predistance=Color distance function for preprocess
  Default: rasta, other options: ciede, yuv, euclid, cie94, oklab

  This option sets the preprocess color distance function to create destination picture.
  For the rest of the optimization the distance set by the /distance is used.
  Note: /predistance=ciede is VERY slow with Knoll dithering (use rasta for faster preprocessing).
  Aliases: --predistance
    
/max_evals=Maximum number of evaluations
  RastaConverter will save the current solution and exit when this limit is reached.
  Aliases: /me, --max_evals

/onoff=OnOff File
  Text file that describes where to turn on and turn off usable registers. The format of each line in "OnOff file" is:

REGISTER OFF|ON FROM TO

  REGISTER is one of the following registers: COLOR0,COLOR1,COLOR2,COLBAK,COLPM0,COLPM1,COLPM2,COLPM3,HPOSP0,HPOSP1,HPOSP2,HPOSP3
  OFF turns off the usage of registers in lines, ON turns on. ON is default for all the registers in the whole picture.
  FROM is line number in picture starting from 0
  TO is line number in picture up to Picture Height-1
  Aliases: --onoff

  Every line in "OnOff file" is processed one after another.

  Example:
  To turn off usage of player 0 and player 1 in picture of height 240 pixels use the following OnOff file:

COLPM0 OFF 0 239
HPOSP0 OFF 0 239
COLPM1 OFF 0 239
HPOSP1 OFF 0 239

/preprocess
  If this switch exists then RastaConverter generates and saves only destination picture.
  Aliases: --preprocess

/seed = seed for the random number generator
  Aliases: --seed

Image processing:

/cache=number
  Default: 64
  Sets number of megabytes per thread to use as memory buffer to speed up conversion.
  Aliases: --cache
   
Dual-frame mode:

/dual
  Enable dual-frame optimization mode (two alternating frames A/B blending). Default: off
  Aliases: /dual, --dual

/first_dual_steps=<N>
  Number of evaluations in initial bootstrap for frame A (and B if /after_dual_steps=generate). Default: 100000
  Aliases: /fds, --first_dual_steps

/after_dual_steps=copy|generate
  After A bootstrap: copy A to B (copy), or generate B from fresh random init and bootstrap it for /first_dual_steps (generate). Default: copy
  Aliases: /ads, --after_dual_steps

/altering_dual_steps=<N>
  Number of evaluations per alternation block during dual Stage 3. Default: 50000
  Aliases: /alts, --altering_dual_steps

/dual_blending=yuv|rgb
  Blending color space for preview/export in dual mode. Default: yuv
  Aliases: /db, --dual_blending

/dual_luma=<FLOAT>
  Temporal luma penalty weight in dual mode. Higher values reduce flicker by forcing A and B to be closer in brightness; lower values allow more alternation range. Default: 0.2
  Aliases: /dl, --dual_luma

/dual_chroma=<FLOAT>
  Temporal chroma penalty weight in dual mode. Higher values reduce color flicker; lower values preserve more color variety. Default: 0.1
  Aliases: /dc, --dual_chroma

/dual_dither=knoll|random|chess|line|line2
  Input dithering type for dual mode. Adds structured noise to the input image before optimization starts, which can help guide the optimizer toward better color distribution. Default: none (disabled)
  - knoll: Bayer matrix-based dithering (similar to Adobe pattern dithering)
  - random: Random noise pattern
  - chess: Chessboard pattern transformed into noise
  - line: Alternating line pattern
  - line2: Similar to line pattern
  Aliases: /dd, --dual_dither

/dual_dither_val=<FLOAT>
  Input dithering strength. Controls the magnitude of noise added to the input image. Range: 0.0-2.0. Default: 0.125
  Higher values add more noise, which can help break up color bands but may reduce accuracy.
  Aliases: /ddv, --dual_dither_val

/dual_dither_rand=<FLOAT>
  Input dithering randomness. Blends deterministic pattern with random noise. Range: 0.0-1.0. Default: 0.0
  - 0.0: Pure deterministic pattern
  - 1.0: Pure random noise
  - Values in between: Blend of pattern and random noise
  Aliases: /ddr, --dual_dither_rand

Syntax example (not a best-quality parameter recommendation):
RastaConverter.exe c64.png /threads=8 /s=5 /opt=lahc
